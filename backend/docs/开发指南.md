# Leadhub 后端开发指南

## 1. 环境准备

- Python 3.11+
- Docker & Docker Compose（用于启动中间件）

## 2. 安装依赖

```bash
cd backend

# 推荐：使用 uv
uv venv .venv
source .venv/bin/activate
uv pip install -e ".[dev]"

# 或使用 pip
python -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
```

## 3. 中间件（PostgreSQL）

默认 PostgreSQL。`make start` / `make backend-dev` 会自动准备——**优先复用本机已运行的**，缺的才用 Docker 起：

```bash
make start    # 复用本机 PG（要求 .env 的用户/密码/库已存在）；没有则 Docker 起独立实例
```

想零依赖单文件：`.env` 改 `DB_TYPE=sqlite`（存 `backend/data/app.db`）。

## 4. 启动开发服务器

在工程根目录：

```bash
make backend-dev
```

或直接：

```bash
cd backend && uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

启动后日志会打印：

```
🔑 默认管理员密码：<默认 admin（--admin-pass 可指定）>（生产环境请立即修改！）
✅ demo 用户已创建：manager / alice / bob（密码均为 Demo@123）
```

启动后访问：

- Swagger UI：http://localhost:8000/docs
- ReDoc：http://localhost:8000/redoc
- 健康检查：`http://localhost:8000/healthz`(进程级)、`/readyz`(含 DB ping)
- 数据库 UI：http://localhost:8080

## 5. VSCode 调试

打开 `backend/.vscode/launch.json` 已包含三种配置：

- **FastAPI: Debug Server** —— 按 F5 一键启动并断点调试
- **FastAPI: Current Test File** —— 调试当前打开的测试
- **Pytest: All Tests** —— 调试并跑全部测试

> 需要先安装 `ms-python.debugpy` 扩展（启动时 VSCode 会提示）。

## 6. 数据库（自动维护）

后端启动时会**自动维护表结构**，无需手动跑 alembic。具体行为：

| 状态 | 行为 |
|---|---|
| 首次启动（数据库无 `alembic_version` 表）| 自动用 `metadata.create_all` 建表 + 插入种子数据（**不**自动 stamp alembic） |
| 后续启动（已有 `alembic_version` 表）| 自动执行 `alembic upgrade head` + 补全种子 |
| 任何步骤失败 | 记录警告但**不阻塞应用启动** |

> ⚠️ 如果 alembic 失败，启动日志会给出**中文诊断**（连接失败/数据库不存在/版本冲突），按提示修复即可。
> 首次启动后请**手动**跑：`make db-migrate MSG="init"` → `make db-upgrade`，建立迁移基线。

## 7. 添加新业务模块

**强烈推荐**用一键脚本（比手写 6 个文件快 10 倍）：

```bash
python3 scripts/add_module.py order --title "订单管理"
```

脚本生成 model / schema / crud / router / 前端 api / 前端页面，随后需 **5 步手动注册**——完整清单以根目录 [AGENTS.md](../../AGENTS.md) 为权威（含改字段流程与 SQLite 迁移注意事项）。

## 8. 默认账号

| 账号 | 密码 | 角色 | 何时创建 |
|---|---|---|---|
| `admin` | 启动时控制台打印（16 位随机） | 超级管理员（is_superuser=true） | 任何环境都创建 |
| `manager` | `Demo@123` | 部门经理（demo 数据） | **仅 dev / test 环境** |
| `alice` | `Demo@123` | 普通员工（demo 数据） | **仅 dev / test 环境** |
| `bob` | `Demo@123` | 普通员工（demo 数据） | **仅 dev / test 环境** |

> ⚠ 生产环境（`APP_ENV=prod`）**只创建 admin**，不创建 demo 用户。
> ⚠ admin 密码启动时控制台打印一次（找不到就用 `make reset-admin` 重置，或 `make admin-pass NEW=YourNewPass!2025` 指定）。

## 10. 常见问题

### Q: 启动报错 `SECRET_KEY 不能为空`

A: `.env` 文件不存在或 `SECRET_KEY` 仍是 `__SECRET_KEY__` 占位符。`make backend-dev` 只会从 `.env.example` 复制（仍是占位符）。正确做法：重新跑 `python3 scripts/init.py <name> --only admin` 生成带真实密钥的 `.env`，或手动 `openssl rand -hex 32` 替换。

### Q: 数据库连接失败

A: 看启动日志的中文诊断。常见原因：
- PostgreSQL 连接失败 → `make start`；复用本机 PG 时确认 .env 凭据在该实例已创建
- 端口被占用 → `make stop` 后 `lsof -i :5432` 查
- 密码不一致 → 重新跑 `make reset-admin` 不影响，DB 密码在 .env

### Q: 改了模型没生效

A: alembic 自动检测版本号自动迁移，但新增字段可能需要手动处理：
- 增加列：自动迁移（默认值）
- 改类型/删字段：SQLite 删 `data/app.db`（或 backend/data/app.db）重启重建 ⚠️（清数据）；PG 备份后删库重建

### Q: 忘了 admin 密码

A: `make reset-admin` —— 重置为 admin；`make admin-pass NEW=xxx` 指定新密码。

### Q: 想重置整个数据库

A: SQLite 删 `data/app.db` 后重启；PG 用 `make stop` 后 `docker compose down --volumes` 再 `make start`。

### Q: 端口 8000 被占用

A: 修改 `.env` 中的 `PORT`，或关闭占用进程：`lsof -i :8000`。

### Q: 想看表里到底有什么

A: 打开 http://localhost:8080（adminer），登录看数据。
