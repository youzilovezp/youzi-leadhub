# Leadhub 后端架构说明

## 1. 分层架构

```
HTTP 请求
   │
   ▼
1. LoggingMiddleware（记录 method/path/duration）
   │
   ▼
2. CORSMiddleware（处理跨域）
   │
   ▼
3. 路由匹配（app/api/v1/router.py）
   │
   ▼
4. 依赖注入
   - SessionDep（注入 AsyncSession）
   - CurrentUser（注入当前登录用户）
   │
   ▼
5. endpoint 函数
   - 入参校验（Pydantic）
   - 调用 Service / CRUD
   │
   ▼
6. 异常处理
   - BusinessError → 业务错误响应
   - RequestValidationError → 422 校验失败
   - 其他 → 500 服务器错误
   │
   ▼
7. ResponseModel 包装（统一响应格式）
```

## 2. 配套模块

| 模块 | 职责 |
|---|---|
| `app/core/config.py` | 统一配置加载（pydantic-settings） |
| `app/core/security.py` | JWT、密码哈希（bcrypt） |
| `app/core/exceptions.py` | 业务异常 + 全局异常处理 |
| `app/core/logging.py` | loguru 日志 |
| `app/middleware/` | CORS、日志中间件 |
| `app/api/deps.py` | 依赖注入（Session、当前用户） |
| `app/schemas/` | Pydantic 请求/响应模型 |
| `app/db/init_db.py` | 启动时自动建表 + 种子数据 |

## 3. 统一响应格式

所有接口返回：

```json
{
  "code": 0,
  "message": "ok",
  "data": { ... }
}
```

| 业务码 | 含义 |
|---|---|
| `0` | 成功 |
| `40001` | 用户名已存在 |
| `40100` | 认证失败（token 无效/缺失） |
| `40300` | 权限不足 |
| `40400` | 资源不存在 |
| `42200` | 参数校验失败 |
| `50000` | 服务器内部错误 |

## 4. 鉴权流程

```
用户打开 /login
  │
  ▼
1. 输入用户名密码 → POST /api/v1/auth/login
  │
  ▼
2. 后端校验 → 返回 JWT token
  │
  ▼
3. 前端把 token 写入 Pinia store + localStorage
  │
  ▼
4. 后续请求自动加 Authorization: Bearer <token>
  │
  ▼
5. router.beforeEach 守卫：
   - 未登录 → 跳 /login
   - meta.requiresAdmin 且不是 superuser → 跳首页
```

## 5. 中间件体系（默认 docker compose）

| 中间件 | 用途 | 端口 |
|---|---|---|
| PostgreSQL | 主数据库 | 5432 |
| Redis | 缓存 / 限流 / JWT 黑名单 | 6379 |
| adminer（可选，手动启动） | 数据库 UI（看数据） | 8080 |

> 后续如需扩展 RabbitMQ / MinIO 等，自行加依赖 + docker-compose service。

## 6. 加新业务模块

运行：

```bash
python3 scripts/add_module.py order --title "订单管理"
```

脚本自动生成 model/schema/crud/router/view/api 六个文件，并提示需要手动注册的 5 处地方。详见 [开发指南](开发指南.md)。
