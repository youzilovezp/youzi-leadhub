# 爬虫引擎诊断报告：发现与富化为什么差，是否该换引擎

> 方法：systematic-debugging（先根因、后方案）。全部结论来自运行库实测（PG 15432）+ 代码审计 + 本机连通性实验，不用感觉说话。
> 日期：2026-09-01

## 0. 结论先行

**没有必要用开源爬虫引擎全方位重构。引擎不是瓶颈——换引擎不会让发现/富化变好一天。**

现有引擎是标准且正确的四层反爬架构（httpx → 宽松SSL/换scheme → curl_cffi Chrome 指纹 → playwright 无头浏览器），与 Scrapy/Crawlee 同一代架构。诊断证据显示：**81 次首页抓取失败中，绝大多数是「喂进去的网站本身就是垃圾/死站」，与引擎无关**。管道表现差的真实原因在引擎**上游**（发现渠道产出垃圾）和**运维配置**（调度关闭、Meta token 未配、指纹层依赖未装、富化无代理通道），每一项都有明确的低成本修法。

## 1. 硬证据：失败归因（运行库实测）

任务日志 1065 条中「首页抓取失败」81 条。逐条归因：

| 失败网站的真相 | 占比 | 代表 | 引擎能做什么 |
|---|---|---|---|
| **政府/事业单位站**（负面清单内的输入） | ~55% | yw.gov.cn、jiangsu.gov.cn、sz.gov.cn、gd.gov.cn、mofcom.gov.cn、singlewindow.cn 等 11+ 个 | 无——这些本来就不该进库，词表没拦住 |
| **假站/内容站**（诈骗域名、词典站） | ~20% | page-whatapps.com.cn、home-whatsapp.com、chagushici.com | 无——域名根本没有真实托管 |
| **死域/证书坏站**（发现时域名已失效） | ~15% | want-want.com（DNS 失效）、meet-in-shanghai.net（证书错误） | 无——已正确诊断并留待下一轮 |
| **真反爬站**（403/503/Cloudflare） | ~10% | banggood 型 | **这才是引擎能解决的**，且四层里有专门的两层（指纹层实测 banggood 403→200） |

**结论：约 90% 的「富化失败」是输入质量问题和站点已死，不是引擎抓不动。** 换 Crawlee 抓 gov.cn 也一样连接拒绝。

## 2. 五个真实根因（按影响排序）

### R1【最大】发现侧在喂垃圾——黑名单词表滞后于渠道产出

- 证据：web_search 渠道 7 条线索全部有官网、富化 5 条、**WA 命中 0 条**——这条渠道产出的全是 gov.cn、假 WhatsApp 站、下载页（小米应用商店、NVIDIA 下载页也在库里）。而 gov.cn 域、下载页、词典站在 §2.2 负清单里**明文排除**。
- 铁证：历史日志里 11+ 个 gov.cn 域名进过富化（现在库里已清，但渠道仍在产出同型垃圾）。
- 根因：黑名单是运营资产（§2.2「实测漏网域持续增补」），但 web_search 的入库前拦截与词表没有闭环——假站和 gov 域在持续漏网。
- 这不是引擎问题，换引擎还会继续喂垃圾。

### R2【最大】管道结构性停摆——三条通道全关

实测 .env：

| 配置 | 当前值 | 后果 |
|---|---|---|
| `SCHEDULER_ENABLED` | **false** | 无定时任务，「每天收到一批」从未自动跑过，发现只靠手动点 |
| `META_ADS_ACCESS_TOKEN` | **未配置** | meta_ads 渠道产出 0 条；这是「唯一 S/A 制造机」（CTWA+40/在投+15 都来自它） |
| curl_cffi | **未安装**（playwright 已装） | 四层抓取的指纹层**静默缺席**（代码里 ImportError → 返回「层不可用」不算失败），403 站直接掉到最重的浏览器层 |

当前库里 69 条线索的来源分布：b2b 38、job 22、search 7、meta_ads **0**。S/A 制造机是死的，当然「表现差」——这是 §9 文档里白纸黑字预期的结构性缺 S/A。

### R3【结构】官网发现吞吐瓶颈——b2b 线索一半卡在没官网

- b2b 38 条里 **21 条没有官网**（档案官网字段多数不填，靠「官网发现」补）。官网发现每轮硬上限 30、3s 间隔（礼貌约束），全库扫描一轮至多补 30 个。
- 无官网 → 富化不了 → 无联系方式 → 三问 who 不齐 → 进不了今日商机。发现做得再猛，都堵在这道闸上。

### R4【引擎配置缺陷，但非主因】富化根本没有代理通道

- 代码审计：meta_ads 和 web_search 都实现了「显式代理优先 + 直连兜底」双通道（读 `CRAWLER_PROXY_URL`），**唯独 website_enrich 构建 client 时不带 proxy**（`website_enrich.py:857`），career_site 的浏览器也是 `proxy=None`。
- 本机实测：127.0.0.1:7890 代理端口**开着**，但 .env 里 `CRAWLER_PROXY_URL` 为空；且本机直连 baidu/google 都通——说明当前环境墙的影响有限，海外真站点（FB 主页、wa.me、Shopify 型站）才是需要代理的场景。
- 影响：海外站点直连慢/被墙 → 富化失败或降速。但**不是当前 81 次失败的主因**（主因是 R1 的垃圾输入）。

### R5【最小】引擎自身：只有 ~10% 失败属于引擎可战之场

403/503/Cloudflare 型站点占比低；且对这类站点，现有架构已有正确武器（指纹层 + 浏览器层）。剩余真正的引擎级短板是**指纹层依赖没装**（R2 第三行）和**部分 502 背后可能是 ISP 干扰**（接了代理再看）。

## 3. 引擎能力对比：换开源引擎能得什么？

| 维度 | 现引擎（四层自建） | Scrapy | Crawlee | 换的收益 |
|---|---|---|---|---|
| 反爬层级 | httpx→宽松SSL→curl_cffi 指纹→playwright | 需自行拼装 middleware | 内置指纹+浏览器 | **≈0**，架构同一代 |
| 异步并发 | asyncio 原生，与任务系统一体 | Twisted 生态，与 asyncpg 打架 | Node 生态，与 FastAPI 跨语言 | 负收益 |
| 节流/礼貌采集 | 已按 §3.4 分窗口实现 | 需自写 | 内置 | ≈0 |
| 检测层（WA/邮箱/JSON-LD/联系页启发/外销英文页） | **已深度定制 2000+ 行** | 无 | 无 | **重构 = 全部重写，净损失** |
| 失败分层诊断 | 已实现（DNS/超时/TLS/HTTP 码/指纹层/渲染层） | 无 | 部分 | 负收益 |
| 增量重爬/负证据闭环/窗口 | 已实现 | 无 | 无 | 净损失 |

**Crawlee 唯一优势是 JS 渲染站的持久化浏览器与更全指纹**——但本库 JS 挑战站占比 <10%，且 playwright 已在。为一个 10% 场景推倒全部检测/评分/闭环逻辑，ROI 为负。

## 4. 修复路径（按 ROI 排序，全部是小动作，不重构）

1. **R2 三个开关**（零代码）：`SCHEDULER_ENABLED=true` + 跑 `seed_cron_tasks.py` 种定时任务 + 申请 Meta 免费 token（§9 运营依赖）→ 恢复「每天一批」与 S/A 制造机。
2. **R2 装依赖**（一条命令）：`pip install curl_cffi` → 指纹层复活，403 站少走一层最贵的浏览器。
3. **R4 补代理通道**（小改，照抄 meta_ads 现成模式）：website_enrich/career_site 构建 client 时支持 `CRAWLER_PROXY_URL` 优先；.env 填 `CRAWLER_PROXY_URL=http://127.0.0.1:7890`。
4. **R1 词表闭环**（运营动作 + 一行代码）：把 gov.cn 域、已知假站（page-whatapps 型）、下载页模式补进买家黑名单；web_search 入库前拦截同步词表（两处同源，§2.2 已约定）。
5. **R3 官网发现提速**（改一个常量 + 裁决）：`_DISCOVER_LIMIT` 参数化默认 30 不变、运营可调；CSV 种子鼓励带 website 字段绕过发现。

**验证指标**（修完对比）：富化成功率应显著上升（垃圾站不再进队列）；meta_ads 线索从 0 → N；S/A 从 5 → 目标区间。

## 5. 什么时候才值得考虑换引擎（条件触发，不是现在）

- 修完 R2/R4 后，对**真实企业站**（非垃圾站）的富化失败率仍 >50%，且失败原因以 403/503/Cloudflare 挑战为主；
- 或出现大规模 JS 渲染站目标群（Shopify 型 >30%），playwright 层成为吞吐瓶颈。

届时值得评估的也只是「局部替换抓取层」（如 Crawlee 持久化浏览器池），**而不是全方位重构**——检测层、去重、ICP、评分、三问、闭环逻辑与引擎无关，永远是资产。
