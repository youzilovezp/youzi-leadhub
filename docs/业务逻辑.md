## 1. 一句话定位（业务重构后）

**自动发现、评估并排序「出海 × 用 WhatsApp 承接客户」的中国企业，让销售每天直接收到一批值得联系的客户**——我们是 WhatsApp 中国 BSP，向他们出售 SaaS 服务（账号/承接客户/精细化运营）与 WhatsApp 消息；不是企业名录，核心价值是回答：这家公司为什么需要你、应该卖什么、应该找谁。

- **客户只面向「目标买家 × 中国企业 × 出海业务」**：ICP 资格门（买家门 + CN/出海门，`collectors/icp.py`）硬性准入——行业媒体/社区/软件页等非买家与外企都不进销售池；资格层之内的**价值靶心 = 已在用 WhatsApp 承接客户**（需求文档 §2.4）
- **招聘只面向中国招聘平台**：jobui/猎聘/前程无忧已落地（Playwright 渲染），BOSS/智联为 STUB
- **双业务线**：SaaS 服务（账号/承接客户/精细化运营）+ WA 消息（BSP 主线）；Meta/TikTok 广告代理为延伸线（同客双报价）——需求文档 §0
- 链路：**采集 → 归一化 → 去重合并 → ICP 资格门 → 意向分加分制（v3）+分级 → 今日商机批次（三问齐备）→ 领取 → 跟进建联 → 成交回传**

## 2.5 ICP 资格门（买家门 + 中国出海门，`collectors/icp.py`）

资格是**销售池准入门**，不是评分软加权。两层判定：先过买家门（不是所有中国企业都是潜在买家），再看 CN×出海证据：

| icp_status | 判定 | 动作 |
|---|---|---|
| `qualified` | CN 证据 + 出海证据 | 进销售池与今日商机批次 |
| `cn_domestic` | CN 证据、未见出海信号 | 培育池（补官网富化后升级） |
| `foreign` | 有评估结论但无 CN 证据 | **默认列表/导出排除**（`icp=all` 可显式看） |
| `non_buyer` | 买家黑名单命中（行业媒体/社区/论坛/报告页/软件下载页/门户导航） | **默认列表/导出/今日商机排除**（同 foreign 口径）；黑名单**优先于** CN/出海判定——媒体站哪怕 CN+出海全占也不进销售池 |
| `unknown` | 证据不足（未富化/判不了买家身份） | 保留在池，标记待验证（不做有罪推定） |

- **买家门**：域名黑名单（跨境媒体/社区/门户 8 域 + letschuhai/iciba + **gov.cn/edu.cn TLD** + 白鲸出海/出海网/海外网/昵图网等媒体域）∪ 名称词表（资讯/社区/论坛/白皮书/报告类/下载/百科/导航/工具箱/协会/学会/36氪 + **政府事业单位**：人民政府/管委会/公共服务平台/海关/商务局等 + **出海中介服务商**：货代/物流/船务/代运营/客服外包——2026-09-01 用户裁决服务商非目标客户）任一命中即 `non_buyer`。name/domain 两样都没有 → 判不了不算 non_buyer。web_search 的门户黑名单**同源补缺做入库前拦截**，这里管存量兜底。**建站/工具 SaaS 服务商（Shopline 类）是买家不误杀**
- **四行业归类是展示标签不是硬门**（2026-09-01 用户裁决：服务商不是目标客户、建站SaaS算买家）：`industry_labels.industry_group_of` 把 industry/公司名归入跨境电商/出海游戏App/制造业出海/出海SaaS工具 四组（`industry_group` 是**读取时派生的展示字段**——列表/详情行返回组键，行业筛选仍走 `industry` 原值；组间首匹配），industry 常缺失，硬门会杀召回——买家排除只走黑名单
- **CN 证据**（任一）：is_cn（中国招聘站来源 / CSV 中国种子 / meta_ads 中文页名 / 官网中文 ≥30% / **ICP 备案号**）｜country=CN｜+86 号码
- **出海证据**（任一）：overseas_signals 非空｜fb_whatsapp｜target_countries 非空｜招聘信号含海外语义岗（wa_ops/overseas_cs/overseas_sales/social_ops——在招海外岗 = 出海业务在运转的直接证据，招聘站来源、无官网企业靠它进销售池；crm_ops 不算，不必然出海）
- 「有评估结论」= enriched_at 非空 或 来源含 meta_ads **且有官网**——评估过才有资格 foreign；无官网的 meta_ads 行保持 unknown（中国出海大卖普遍英文品牌英文素材，探测失败拿不到官网时保留翻案通道，不做有罪推定）
- 与评分同点重算（`apply_score` 写回），upsert/富化/联系人变更均触发；stats 有 `icp_counts` 五态分布
- **CN 证据分级**：`icp.cn_evidence_of` 区分 strong（country=CN / +86 / 中国招聘站来源 job_posting·career_site / 人工录入·种子导入）与 weak（**仅 CJK 启发式**——web_search 中文标题 / meta_ads 中文页名 / 官网中文 ≥30%；东南亚华人本地企业同样命中，是 qualified 误判的主要入口）。弱证据不拒之门外但必须可见：详情页 qualified+weak 打「CN 待核验」标（`detail.cn_evidence`），质量抽检 overseas 维**弱证据优先出队**——先量化误判率再决定是否收紧

## 4. 采集器体系（插件式）

`backend/app/collectors/base.py` 定义契约：采集器实现 `run(ctx)`，通过 `ctx.emit(draft)` 落库、`ctx.log()` 写日志、`ctx.check_cancelled()` 响应取消。`collectors/__init__.py` 的 `_REGISTRY` 注册即接入任务体系/去重/评分，前端表单由 `param_schema` 动态渲染。

**param_schema 控件类型**（`type` + `options` 字段，2026-08-27）：`select`（可搜索下拉，国家/目标市场 15 国选项 + 允许手输）、`cities`（城市联动输入：`depends_on` 指向国家字段，选中后出该城市建议，仍可手输任意城市）、`tags`（标签输入，回车追加多个，提交时 join 逗号）、`multiselect`（预设选项多选）、`switch`（布尔开关，提交 `true`/`false` 字符串）、`number`（整数输入）、缺省 `text`（普通文本）。提交值统一序列化为字符串（后端 `split_csv`/`_parse_bool` 消费），必填校验前端先拦、后端 `validate_params` 兜底。

### 4.0 meta_ads（主通道：中国出海企业挖掘，2026-08-30）

ICP 反转后的核心获客链路——**挖「在投海外广告的中国企业」**：

- **入口**：Meta 官方广告资料库 API（`ads_archive`，v22.0），按「关键词 × 投放目标国」搜**在投**广告（`ad_active_status=ACTIVE`，必填 `ad_reached_countries`），每关键词翻页≤N（默认 2 页 × 100 条）
- **默认关键词 = 跨境大卖常见品类词**（smart watch/leggings/wig/shapewear/led strip light/phone case/jewelry/game，表单预填一键创建）——挖的是「在投海外广告的中国企业」，按品类词填命中面最大；投放国默认预填 WhatsApp 高渗透市场（东南亚 + 中东：MY/SG/ID/TH/PH/VN/AE/SA）
- **聚合**：按 `page_id` 去重广告主，记 page_name / profile_uri / 广告数 / 文案样本
- **主页探测**（`probe_pages` 开关，默认开）：双通道网络（系统代理优先——国内直连 Meta 域被墙；失败/软拦截切直连兜底）抓主页 HTML，提取：
  - `wa.me/<号码>` / `api.whatsapp.com/send?phone=` → **对方的 WhatsApp 号码**（销售建联第一入口，补 `+` 按国际号解析）+ `fb_whatsapp=True`（CTWA/私域运营证据）
  - 联系邮箱（复用 website_enrich 的检测与平台埋点黑名单）
  - 外链官网（解 `l.facebook.com/l.php?u=` 跳转 + 裸链接，滤平台域）→ 走 domain 去重
  - 中文特征（品牌名/文案含 CJK）→ `is_cn=True`（销售可筛「中国出海」）
- **只爬公司/企业**：主页类目标签（`categoryName`）命中非企业黑名单（公众人物/自媒体/媒体/政府/艺人/学校/宗教…，中英双语）→ 跳过不入库；企业类目映射中文存 `industry`（Shopping & Retail→零售 等）。拿不到类目（登录墙）保守放行——不误杀；探测关闭时无法判定类型，建议开着跑
- **CTWA 口径**：API 不暴露广告 CTA 类型（接口限制）；「主页挂 wa.me + 持续在投广告」= 已用 WA 做私域获客的可靠代理信号
- **凭据**：`META_ADS_ACCESS_TOKEN`（.env，**全程免费 0 元**：https://www.facebook.com/ads/archive/api 申请，Meta 开发者账号 + 建应用 + 生成 token 都不收费，无需投放广告，只需 ads_archive 只读权限）。缺失任务直接 failed 带指引；无效（code 190）→ 每次请求记 error 日志，最终「全部关键词查询失败」判 failed，不产出空结果假成功
- **纪律**：主页探测间隔 ≥1.5s、翻页 ≥0.5s；单页探测失败记 warn 继续（登录墙/网络抖动不挡产出）
- `country` 语义：多国投放时统一记第一个投放国（单值列），明细看任务日志

### 4.1 web_search（免费搜索引擎发现）

- 默认引擎 **duckduckgo**（零 key）；DDG 失败自动降级 **cn.bing.com 直连**（keep-alive + 3 次退避重试）。可选 `SEARCH_ENGINE`：searxng / google_cse / bing / bing_cn（必应中国版）
- **默认关键词 = 目标行业业务词**（跨境电商 独立站 客服 / 外贸 whatsapp 私域 / 海外私域运营 whatsapp / 跨境 电商 官网 客服 / 出海品牌 独立站 客服——表单预填一键创建）。口径 = 中文长尾**业务词**（客服/私域/官网类组合）；名词类品类词（制造业/品牌）的搜索结果页全是词典与文章页（2026-09-01 实测教训）；只搜 whatsapp 一个词结果全是软件下载页
- 只收企业官网种子：平台/社媒/门户域黑名单（facebook/amazon/alibaba 等平台、社媒与门户域，含与买家门同源的 8 个跨境媒体/社区/门户域——在这里**入库前拦截**，`icp.is_non_buyer` 管存量兜底）+ 文章页特征过滤 + 同域去重，入口归一为站点根 URL。黑名单是实测漏网清单，白鲸出海等出海游戏媒体域未收录（backlog）
- 标中国企业是**双条件**：is_cn 参数开 ∧ 结果标题含 CJK（防海外站误标；英文标题留给富化判定）

### 4.3 website_enrich（富化，非采集源）

- **改存量线索**。范围 = `lead_ids` 指定（列表勾选入口，不受窗口限制）或全库「有网站 且 分级窗口内未成功富化」（S 1天 / A 3天 / B 7天 / C 30天，详见下方分级重爬）
- 抓取**四层递进**：① httpx 双通道（主 client 代理优先 + 宽松 SSL 直连兜底，首页失败换 scheme 再试）→ ② curl_cffi Chrome TLS/HTTP2 指纹伪装（毫秒级，大多数反爬站到此为止）→ ③ 无头浏览器渲染（JS 验证挑战站终极兜底，未装 playwright 可选依赖时静默降级）。内页 = 首页 + 最多 3 个同域内页（contact/about/product/shop 类链接，跨境电商站的品类/交易词主要来源）
- **联系方式是富化的第一产出**：公开邮箱（**首页+内页全扫**，mailto 跨页优先——2026-08-31 三次巡检：此前只扫首页，联系页邮箱全漏）→ 自动「待补全」联系人；WhatsApp 号码 → 自动联系人（电话即号码，销售直接建联）；tel: 链接电话 → 线索电话（E.164 归一）。**内页与首页同等待遇**（`_fetch_site` 双通道兜底，此前单次主 client 请求——代理软拦截站点首页成功联系页全挂）
- 结束日志区分「成功 X、失败 Y」并按站点列出失败原因（DNS/超时/TLS/HTTP 状态码/指纹层/渲染层分层诊断）；**失败原因同时落到线索 `field_meta.enrich_fail`（每条线索最近一次失败的原因/时间/站点，零迁移 JSON 列），详情页「富化失败」行展示、成功富化自愈清除**
- **抓取健壮性**：网络双通道（2026-08-31 起，详见 §4.5）——主 client 代理优先，宽松 SSL 兜底 client `trust_env=False` 直连。历史 P0（2026-08）：代理软拦截返回 202 造成「首页抓取失败」误报；现语义为「死代理 → 兜底直连仍成功」（回归测试本地回环验证）
- 检测：WhatsApp 指纹（wa.me / api.whatsapp.com / ht-ctc·joinchat·getbutton·chaty·elfsight 等插件特征）+ mailto 邮箱（资源文件名防误判）+ 5 平台社媒（FB/IG/LinkedIn/TG/TikTok）
- **场景 & SaaS 需求识别**：页面文本关键词命中（`collectors/scenes.py`，ASCII 整词 \b 词边界防 "about"误中"bot"）→ WhatsApp 场景（客服/营销/交易通知/SaaS）与 SaaS 信号 8 类（CRM/工单/Chatbot/AI 客服/营销自动化/全渠道 + **wa_bsp 竞品栈**：Wati/360dialog/Gupshup 等 18 个 BSP 品牌指纹 + **brand_stack 通用 SaaS 技术栈**：intercom/gorgias/zdassets(Zendesk)/hubspot/hs-scripts/salesforce/zoho/freshdesk/crisp.chat/tawk.to 等 13 词——品牌 widget 嵌在 script/link 标签里，剥标签即丢，与 wa_bsp 同走 **raw HTML 指纹匹配**；命中 = 在为海外客服/营销买 SaaS 工具，是「应该卖什么」的强素材，不进意向分），union 单调合并；抓到公开邮箱自动生成「待补全」联系人（`crud/contact.auto_create_from_email`）
- **号码证据链（补充需求 §4.1）**：`detect_whatsapp_numbers` 收集页面全部 wa.me 号码（去重）→ `whatsapp_numbers` 列表（多分线 = 规模化私域证据，命中意向分 multi_numbers +10；前 3 个自动生成电话联系人=建联入口）；meta_ads 主页探测同样累计
- **分级增量重爬（补充需求 §九）**：全库扫描按等级 S 1天 / A 3天 / B 7天 / C 30天；`ENRICH_INTERVAL_HOURS` 作 C 级兜底（默认 720h = 30 天口径）；手动勾选不受限
- **只在成功抓到首页时写 `enriched_at`**——失败/超时下次自动重跑
- **负证据闭环（2026-08-31 三次巡检）**：复查成功抓到首页但未复现已记录的 WhatsApp 入口 → 发 `whatsapp_gone` 事件进时间线（不翻布尔列，历史事实保留）；详情页信号证据带 `stale_days`（距最近复现天数，前端 ≥90 天标「N 天未复现」）
- **终态不再富化**：won/invalid 线索退出全库重爬范围（省配额；NULL 从未跟进的共享池用 `or_` 显式放行——`NULL NOT IN` 陷阱会滤掉全部未跟进线索）
- **内页发现匹配 href 或锚文本**（联系我们/产品中心等中文锚文本与 /contact 英文 href 一并覆盖——中文官网此前漏大半）
- 两个入口一执行路径：列表勾选 → 隐式任务；手动/定时建任务 → 全库 eligible

### 4.4 job_posting（中国招聘站信号巡检，多站架构）

**巡检模式（默认）**：只给**库内已有公司**补招聘信号——岗位帖按公司名+城市走三身份列反查，命中库内才合并信号重评分，反查不中**不建行**（`upsert_lead(create_if_missing=False)`，返回 None 不抛错）；「发现新线索」开关（`discover_new`，默认关）打开后才作为新线索来源建行。招聘数据的价值是**信号**不是公司发现——招聘站挖来的公司普遍无官网，富化无米下锅，「为什么需要你」永远答不上。页日志报「命中库内 Y 家 / 跳过库外 Z 家（巡检模式）」；巡检跳过的库外公司不计入新增/合并计数。

反爬实测地图（无头 Playwright 实测，据此决定接入范围）：

| 站点 | 状态 | 实测结论 |
|---|---|---|
| jobui 职友集 | ✅ 接入 | 渲染过 valid.php 挑战，`c-job-list` 职位卡 |
| liepin 猎聘 | ✅ 接入 | 渲染出完整职位卡：`job-card-pc-container` 锚点 + `data-nick` 稳定标识 + `title` 属性带职位名；`/a/`（猎头代发）`/job/`（企业直发）两种详情链接；匿名代发（「某…公司」）跳过 |

- **默认关键词 = 中文岗位词组合**（跨境电商客服/英语客服/海外社媒运营/私域运营/外贸业务员/海运客服，表单预填）——站内搜索不吃英文词（「whatsapp运营」会联想跑偏），单词会被模糊匹配稀释，多词组合才有效
- 中国站来源 → `is_cn=True` + `country=CN`；岗位标题分类（`job_signals.py`）→ wa_ops/overseas_cs/social_ops/crm_ops/overseas_sales，信号级证据入 `lead_signals`

### 4.6 career_site（企业招聘官网巡检，2026-08-31）

- **定位**：巡检**库里已有线索**的企业官网招聘页（官网栏目 / Moka、北森、jobs.51job.com 子域等 ATS），从一手在招岗位提取招聘信号——不产生新线索，产出经 upsert 三身份列反查**合并回原线索**（website 相同 → domain 命中同一条）并重评分
- 链路：官网首页（复用 website_enrich 双通道）→ 找「招聘」链接（锚文本/URL 命中 招聘|加入我们|人才|careers|jobs|recruit，外链 ATS 域放行）→ 无链接再探 /careers /jobs /join-us 等常见路径 → 招聘页 httpx（薄壳 SPA 转 Playwright 渲染兜底）→ 页面文本逐条过 `classify_job_title`（**分类器即过滤器**，不命中词表不算岗位）
- 证据置信度 90（企业一手招聘页 > 平台列表的 85）；`skip` 参数轮换巡检（第 2 轮填 20、第 3 轮填 40），按分数倒序每轮默认 20 家
- 不进自动富化接力（不是发现源，线索已在库）

### 4.5 website_enrich（富化 + 官网发现补全链，2026-08-31）

- **官网发现（全库扫描模式前置步骤）**：无官网且非 foreign 的线索（分数倒序、每轮上限 30、3s 礼貌间隔）→ 公司名走搜索引擎找官网（复用 web_search 的平台/文章页过滤与根 URL 归一，DDG 不可达自动切必应）→ 写 website+domain（source=web_discovery, confidence=60）→ 本轮直接富化。否则 jobui 线索永远进不了富化/评分链路、cn_domestic 升不了 qualified
- **发现负缓存（2026-08-31 巡检修复，A 级 bug）**：发现失败的线索分数不变，会永远占着「分数倒序前 N」窗口、后面的线索饿死——失败/撞域写 `field_meta.website` 负缓存标记（web_discovery_miss / web_discovery_dup），7 天冷却不再消耗搜索配额
- **撞域守卫（同日修复，B 级 bug）**：发现链直接改行会绕过 upsert 去重——写入官网前必查 domain 是否已被其他线索持有（`_domain_taken`），撞域则标负缓存跳过，不造永远无人合并的重复线索
- CN 证据优先级：**ICP 备案号**（正则，+cn_icp 信号证据，防纯英文站误杀）> 中文内容 CJK≥30%
- 网络双通道：主 client 代理优先（海外站本机需系统代理）→ 宽松 SSL 兜底 client `trust_env=False` 直连——单死代理不造成「抓取失败」误报

## 5. 去重合并（系统的心脏，`crud/lead.py:upsert_lead`）

1. **归一化**（`collectors/normalize.py`）：
   - 电话 → E.164（phonenumbers，用来源国兜底补国家码；解析失败不参与去重）
   - URL → registrable domain（tldextract 公共后缀表，www/路径/参数全剥）
   - 公司名 → 小写 + 去标点 + 剥法律后缀（Sdn Bhd / PT / Ltd / Pte…）
2. **主键优先级**：`domain:` > `tel:` > `namecity:`(md5(归一名+城市))；三键全空用 `raw:原始名小写|source` 兜底（宁漏勿重）
3. **跨来源合并的关键**：不能只比 draft 自己的主键——存量行主键可能是 `tel:`，新数据带官网进来是 `domain:`。用**三身份列（domain / phone_e164 / namecity_key）OR 反查**，任一命中即合并到最早那条；合并后主键升级收敛到 domain（有冲突则保留旧键）。`create_if_missing` 参数（默认 True）= 巡检开关：False 时三身份列反查不中**不建行**返回 None（job_posting 巡检模式用，§4.4），其余采集器不受影响
4. **合并语义**：
   - 标量字段补空（country/city/website/email/phone…）
   - 布尔 OR（`whatsapp_hit`）；`whatsapp_job` 带语义自愈——合并后 job_signals 无 wa_ops 证据则重置 False（防存量脏 True 虚高意向分 wa_ops_job +30）
   - `job_urls` / `social` 并集
   - `last_ad_at` / `ad_count` 均取 max（meta_ads 最近投放/累计广告数——2026-08-31 巡检接线，此前列恒空）
   - **domain 受 `uq_leads_domain` 部分唯一索引约束（迁移 f7c2a91d4e21，2026-08-31 三次巡检）**：去重不变量下沉 DB——存量同域重复清洗（保留每组最早一行，其余 domain 置 NULL），并发双写同域由索引兜底（upsert savepoint 退化为合并、官网发现链撞域标负缓存、合并补空 domain 前查持有者）
   - 来源记录按 `(lead, source)` 唯一 touch（cron 重复跑不膨胀）
   - **采集器 draft 自动生成联系人并重评（2026-08-31 巡检）**：email →「待补全」邮箱联系人；`whatsapp_numbers` 前 3 个 → 电话联系人（建联入口）。此前 meta_ads 抓的邮箱只落 lead.email 列，三问「应该找谁」永远无真实建联入口；手工录入 source=manual 不自动生成
   - 重算评分

存量行口径迁移：评分/ICP/export_type 规则变更后跑 `scripts/reeval_leads.py` 全库重评（与采集器写入同函数）。

## 6.5 三问生成器（`collectors/intent.py`）

产品核心价值的落点——「为什么需要你 / 应该卖什么 / 应该找谁」从数据里组装成一等公民结构 `three_questions`（纯函数、无 IO、无新增采集），详情页与今日商机行直接消费：

- **Q1 为什么需要你（why）**：意向分明细 top-3 证据，按分值降序——每条 = {信号中文标签, 分值, 证据 URL}（岗位帖 URL / 官网 / wa.me 入口，可点开核对）
- **Q2 应该卖什么（what）**：需求类型（A-F）+ 推荐产品 + 切入场景（中文标签）+ SaaS 信号标签（wa_bsp 标「（在用）」、brand_stack 等——在用什么工具就知道该替换/集成什么）
- **Q3 应该找谁（who）**：两档，**永不空**——
  - 一档：真实建联入口——联系人（tier1 决策层 > tier2 > tier3 排序取前 3）/ WhatsApp 号码（号码即建联入口，取前 3）/ 官网 WA 入口
  - 二档（无联系人时，按信号派生目标角色）：wa_ops → **WhatsApp/私域运营负责人**｜overseas_cs → **海外客服负责人**｜crm/crm_ops/helpdesk/chatbot/ai_service/营销自动化/全渠道/brand_stack → **CRM/客服系统负责人**｜fb_whatsapp（CTWA 人群）→ **海外营销负责人**｜兜底 **海外业务负责人**；每条带「去哪找」提示（招聘页/官网联系页/FB 主页）
- **齐备 = why≥2 条证据 ∧ what≥1 个推荐产品 ∧ 真实建联入口（联系人 / WA 号码 / WA 入口任一）**——roles 只是方向提示**不算**建联入口；齐备是今日商机的入选门槛（§8），不齐备的行不进批次

## 7. 任务生命周期

```
pending ──run/enqueue──> queued ──worker认领──> running ──┬─> completed
   ↑                                                      ├─> failed（业务异常/超时/重启中断）
   └──────────────── 再次执行 ←── cancelled ←──────────────┘
```

- **task_runner.py：DB 即队列**（无 Redis/Celery）。N 个 worker 协程（= `COLLECT_MAX_CONCURRENT`，默认 2）轮询 `UPDATE..RETURNING` 按 id FIFO 认领
- **采集流水线自动接力（2026-08-31 交互改造）**：发现类采集器（web_search/job_posting/meta_ads）任务成功完成 → 自动排入隐式 website_enrich 全库扫描（官网发现+信号复核+重评分）。种子要靠富化才有信号、才能过 ICP 门——这个先后依赖以前要用户记顺序手动跑两步，现在系统承担。`AUTO_CHAIN_ENRICH` 开关（默认开）。去重只认「已有全库富化（params 为空）在 pending/queued」——排队中的那次扫描必然覆盖本批新增线索；不看「最近跑没跑过」（时间窗口节流会漏掉窗口后新增的整批线索，同日修复），多余的接力也只是分级增量选库的廉价空扫（job_posting 默认巡检模式不新增线索，接力同样只是廉价空扫）。接力动作写入原任务日志（「已自动接力网站富化任务 #N」）
- 并发闸门满 = 新任务状态留 queued 自然排队，cron 触发**排队不失败**
- 执行期间进度 **5 秒节流写库**（长任务详情页不恒 0，重启最多丢 5 秒进度），收尾一次写终值+计数；`asyncio.wait_for` 超时（`COLLECT_TASK_TIMEOUT`）
- 取消 = 排队中直接 cancelled；运行中置 `cancel_event`，采集循环逐条 `check_cancelled()`
- **进程重启把 running 重置为 failed**
- **scheduler.py**：APScheduler 3.x，仅 `SCHEDULER_ENABLED=true` 的单进程启动（多 worker 只开一个）；cron 存 DB 重启自动恢复；`sync()` 全量重建 job（幂等），触发动作就是 `enqueue`

## 9. 关键设计取舍

| 决策 | 理由 |
|---|---|
| DB 做队列，无 Celery/Redis | 任务量级小（并发 2），重启不丢、零中间件 |
| 勾选检测 = 隐式任务 | 复用进度/取消/闸门/日志全套，两入口一执行路径 |
| 富化只记成功时间 | 失败站点天然可重试，不用单独失败队列 |
| 来源 (lead,source) 唯一 | 防 cron 定时跑把 JSON 数组刷爆 |
| 三身份列反查合并 | 单一 dedupe_key 无法覆盖跨键合并（tel 存量 + domain 新数据） |
| httpx + curl_cffi + Playwright 三层而非爬虫框架 | 按量级选型：日均几十~几百站的礼貌采集，框架的队列/autoscaling 是过度设计；三层递进（httpx→Chrome 指纹→浏览器渲染）覆盖反爬，Scrapy 的 Twisted 与 asyncio 冲突 |

## 10. 技术栈与依赖理由

| 依赖 | 用途 |
|---|---|
| curl_cffi | Chrome TLS/HTTP2 指纹伪装——反爬只认指纹的站点不开浏览器直接过（实测 banggood 403→200） |
| Playwright（`pip install '.[collect]'`） | 无头浏览器渲染：JS 验证挑战站（jobui/猎聘/前程无忧/招聘 SPA 页）与指纹层也过不去的终极兜底 |
| httpx[socks] | 富化/搜索/广告库探测；SOCKS 代理支持（双通道：系统代理优先 + 直连兜底） |
| phonenumbers | E.164 电话归一化（libphonenumber 官方移植） |
| tldextract | registrable domain（公共后缀表，去重键正确性依赖） |
| APScheduler 3.x | 定时调度（锁 <4，API 不兼容） |
