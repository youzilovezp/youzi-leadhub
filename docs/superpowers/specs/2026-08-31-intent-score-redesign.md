# 商机意向分重设计（Intent Score Redesign）设计文档

> 日期：2026-08-31 ｜ 分支：feature/lead ｜ 状态：已与产品负责人逐节确认
> 需求依据：`~/Downloads/whatsapp`（早期完整版，产品定位出处）+ `~/Downloads/whatsapp2`（终版，MVP 加分制/信号体系出处）

---

## 一、背景：定位承诺 vs 系统实况

产品定位（PRD 原文，与 `docs/业务逻辑.md` §1 一致）：

> 自动发现、评估并排序「最可能购买 WhatsApp 消息服务 + 出海 SaaS」的中国出海企业，让销售不再找客户，而是每天直接收到一批值得联系的客户。核心价值是回答三个问题：这家公司为什么需要你、应该卖什么、应该找谁。

重设计启动时（2026-08-31）开发库实况（268 条线索）：

| PRD 承诺 | 实况 |
|---|---|
| 发现跨境电商/游戏/DTC 等中国出海企业 | 95% 来自国内招聘站（job_posting 254 + web_search 14），meta_ads 产出 0 条（token 未配置） |
| 评估并排序，S/A/B/C 优先级 | **268 条全部 C 级，最高 36 分**，0 个 S/A/B——排序名存实亡 |
| 「为什么需要你」 | whatsapp_hit 1/268；判别信号（CTWA/官网WA/出海证据）在数据里几乎不存在 |
| 「应该卖什么」 | 推荐规则依赖信号触发，无信号即无推荐 |
| 「应该找谁」 | 有联系人 6/268（2%），且全是「待补全」泛邮箱 |
| 「每天收到一批」 | 今日商机结构性为空（门槛 ≥60 分，库里 0 条达标） |
| 目标是买家企业 | 榜首是行业媒体/社区/软件下载页（雨果跨境、知无不言、跨境知道、WhatsApp 下载页） |

**根因链**：六维评分的判别信号几乎全由 meta_ads + 官网富化产出 → meta_ads 停摆、招聘站公司 92% 无官网 → 富化无米下锅 → 全员 C → 今日商机恒空。**系统结构上依赖的两条通道恰好没在产出，实际在产出的招聘通道天然给不出三问证据。**

产品负责人确认的差距（四层面全中）：发现方向反了、评分排序失真、三问基本没答案、业务逻辑整体推倒重设计。

## 二、约束与决策记录

| 决策点 | 结论 |
|---|---|
| 预算 | **纯免费**（2026-08-31 硬约束延续）：零付费 API、零采购；企查查类企业库与联系人供应商继续不做 |
| 主通道 | **Meta 广告库 API**（免费 token）——产品负责人负责申请配置（facebook.com/ads/archive/api） |
| 重设计边界 | **底座留、业务层重做**：任务系统/去重合并/线索池/跟进工作流/RBAC/质检页不动；重做发现策略、ICP 判定、评分模型、三问生成、每日交付 |
| 存量数据 | 不清零；仅清买家黑名单命中的污染（备份后删） |
| 成功标准 | **质量优先小闭环**：50–100 条三问齐备的 S/A 真商机，人工核一遍觉得靠谱即算成 |

## 三、设计 §1：商机意向分 v3（评分模型重建）

### 3.1 从「企业质量分」回到「商机意向分」

| | 旧（六维加权） | 新（加分制 v3） |
|---|---|---|
| 分数含义 | 这家公司整体有多好 | 这家公司**现在有多需要你**（WhatsApp 商机意向） |
| 模型形态 | 6 维加权，75% 权重（WA 30%+出海 25%+SaaS 20%）押在无数据通道 | PRD §五 MVP 加分制，每 1 分可溯源到一条证据 |
| 依据 | whatsapp 早期版「成熟阶段」公式——PRD 写明需成交数据回传后训练，当前零成交数据 | whatsapp2 定稿：「MVP 阶段直接加分制——简单、可解释、可调参」 |
| 判别力 | 全库最高 36，满分证据锚点仅 63/A，S 不可达 | PRD 范例 S=87 型（CTWA+官网WA+海外客服招聘=85）自然到 S |

> 历史注记：旧版 8 布尔加分制（不封顶 110 分）于 2026-08-30 废弃，废弃理由是**信号集贫瘠**（无出海/SaaS 细分），不是加分制形态错误。v3 是 PRD §五的 13+ 信号封顶加分制，非回退。

### 3.2 评分表（信号 × 分值，全部为系统已可检测信号）

| 信号 | 检测来源 | 分值 |
|---|---|---|
| CTWA 私域代理（主页挂 wa.me + 在投海外广告） | meta_ads 主页探测（`fb_whatsapp` + meta_ads 来源） | **+40** |
| 在招 WhatsApp 运营岗 | job_posting / career_site（wa_ops） | **+30** |
| 已用其他 WhatsApp BSP（Wati/360dialog/Gupshup 等 17 品牌栈） | website_enrich（wa_bsp） | **+30** |
| 官网 WhatsApp 入口 | website_enrich（whatsapp_hit） | **+25** |
| 在招海外/英文客服岗 | job_posting（overseas_cs） | **+20** |
| WhatsApp Business 业务号 | 富化号码形态（沿用现有六维检测规则） | +15 |
| 在投 Meta 海外广告 | meta_ads 来源 | +15 |
| 出海业务证据（overseas_signals 非空：官网多语言/海外文本信号） | website_enrich | +15 |
| 海外独立站（website 非空 ∧ 出海证据非空，可与上一行叠加） | website_enrich | +10 |

| **封顶** | | **100** |

**互斥规则**：CTWA（+40）成立时**替代**「在投 Meta 广告」（+15），合计 40 而非 55——CTWA 已隐含在投事实。

**不进主分的信号**：
- 通用 SaaS 需求信号（crm/helpdesk/chatbot/AI客服/营销自动化/全渠道）——回答「应该卖什么」（三问之二），进需求类型与产品推荐层。唯一例外 wa_bsp（竞品栈 = 换用迁移意向，是 WA 意向本身）
- 规模/营销量信号（招聘量、广告数、来源数）——降为展示信息，不参与排序（上一轮全员 C 的噪音源）

### 3.3 等级阈值与锚点案例

S ≥80 · A 60–79 · B 40–59 · C <40（PRD 口径不变）。锚点：

| 锚点 | 信号构成 | 得分 | 等级 |
|---|---|---|---|
| PRD 范例（CTWA 跨境电商） | CTWA 40 + 官网WA 25 + 海外客服招聘 20 | 85 | **S** |
| 官网私域型 DTC | 官网WA 25 + 出海 15 + 独立站 10 + 3国 10 + 社媒 5 | 65 | A |
| WA 运营在招的中型企业 | wa_ops 30 + crm 10 + 出海 15 | 55 | B |
| 有出海无 WA 的工厂 | 出海 15 + 独立站 10 | 25 | C（培育池） |
| 竞品迁移型 | wa_bsp 30 + 官网WA 25 + 出海 15 | 70 | A |

### 3.4 落库与迁移

- 复用现有列：`score`（总分）+ `score_breakdown`（加分明细，本就为加分制设计）+ `grade`
- `score_signals` 六维格式废弃：列保留、不再写入（零迁移；历史值随首次重评被覆盖口径替代，读取方全部切到 `score_breakdown`）
- `apply_score`（`crud/lead.py`）保持唯一写入口，评分/ICP/export_type 同点派生的架构保留
- `SCORING_DIM_WEIGHTS` 环境覆盖机制废弃（无权重维度；分值走常量表，调整改代码）
- 存量切换：`scripts/reeval_leads.py` 全库重评一遍完成口径迁移

## 四、设计 §2：ICP 门从「中国企业门」升级为「目标买家门」

现状四态只回答「是不是中国企业 + 出没出海」，不回答「是不是会买东西的目标行业买家」——媒体/社区/软件页全部 qualified 进榜的根因。v3 在门前加买家判定：

```
入库拦截（采集层词表/域名过滤）
   ↓
ICP 三重门（collectors/icp.py）
   ① 买家判定（新增）：PRD 五类目标行业的企业本体
      —— 不是媒体/社区/论坛/软件页/工具站/平台门户/招聘平台
   ② CN 证据（保留 strong/weak 分级）
   ③ 出海证据（保留现有口径：overseas_signals/fb_whatsapp/target_countries/海外语义岗）
   ↓
三门全过 = qualified（销售池）
```

- **买家黑名单**（词表 + 域名双层）：行业媒体/资讯站/社区论坛/软件下载页/工具站/平台门户/招聘平台。web_search 门户黑名单补缺（雨果跨境、知无不言、跨境知道、雨果网等本轮漏网域）；meta_ads 类目黑名单已有基础；jobui 无官网公司靠公司名 + 行业词判定
- **行业白名单映射**（PRD §二五类）：跨境电商/独立站 DTC、出海游戏/App、制造业出海、出海服务（营销/物流/客服外包）、出海 SaaS——基于 `collectors/industry_labels.py` 映射五类标签落 `industry`，可筛选
- 证据不足判不了买家身份 → 进库标 unknown 待富化后判，不做有罪推定（沿用现有原则）
- **存量清洗**：买家黑名单跑库，命中的先备份 CSV 再删（沿用外企清空操作惯例）

## 五、设计 §3：发现通道职责重排

| 通道 | 现状 | 重设计后 |
|---|---|---|
| meta_ads | 产出 0 条（token 未配） | **主发现通道**：关键词（五行业定向词）× 投放国（US/EU/SEA/MEA）挖在投广告；主页探测 wa.me（CTWA 代理 +40）。代码已完整，只欠 token |
| web_search | 泛词搜索，漏进媒体社区 | 定向种子通道：五行业中文长尾词库 + 门户黑名单补缺 |
| website_enrich | 画像主力 | 不动，仅补一项检测：通用 SaaS 品牌栈（Zendesk/HubSpot/Intercom 等，PRD §六要求）→ 进「应该卖什么」素材 |
| job_posting | 新线索主源（254/268 来源，92% 无官网 → 全员 C 祸首） | **降级为信号巡检器**：默认按库内公司名搜岗位，命中库内 → 信号合并回线索（career_site 同款模式）；**库外公司不再入库**。「发现新线索」开关保留、默认关 |
| career_site / CSV 导入 | — | 不动；CSV 继续做存量客户/展会种子入口 |

核心逻辑：招聘数据的价值是「信号」不是「公司发现」——招聘站挖来的公司没官网，富化无米下锅，「为什么需要你」永远答不上。

## 六、设计 §4：三问生成器（新模块 `collectors/intent.py`）

纯函数组装层，不新增采集，从已有数据派生三问，落成一等公民数据结构（不再是前端拼凑）：

- **Q1 为什么需要你（why）**：top-3 证据（信号中文标签 + 分值 + 证据 URL + 发现时间）。数据源 `lead_signals` + `score_breakdown`，基础已有 95%
- **Q2 应该卖什么（what）**：需求类型 A–F（已有）+ 推荐产品（`collectors/recommend.py` 6 规则）+ 切入场景（`collectors/scenes.py`）+ 新补 SaaS 品牌栈
- **Q3 应该找谁（who）**：两档，**永不空**
  - 一档：已抓到的联系人 / WA 号码（号码即建联入口）/ 邮箱
  - 二档（无联系人时，规则派生目标角色）：wa_ops 招聘→私域运营负责人 · overseas_cs→海外客服负责人 · crm 信号→CRM 负责人 · CTWA/官网WA→海外营销负责人 · 兜底→海外业务负责人；输出「角色 + 去哪找」（招聘页/官网联系页/WA 入口）
- **三问齐备度** = why≥2 证据 ∧ what≥1 产品 ∧ who≥1（联系人/号码/角色）→ 今日商机入选门槛
- API：详情页/今日商机行输出 `three_questions` 结构体；前端今日商机三问列与详情页改读它

## 七、设计 §5：今日商机交付

- 入选 = 当日新晋 S/A（grade_change 事件）+ 当日新增 ≥60 分 qualified + 当日高价值预警切片，**加三问齐备门槛**
- 排序：意向分倒序；空态根因诊断（pipeline_health：token/调度/qualified 数）保留

## 八、设计 §6：一次性迁移与清洗

1. 买家黑名单跑库 → 污染线索备份 CSV 后删除
2. 全库按 v3 重评（`scripts/reeval_leads.py`）
3. `score_signals` 六维 → v3 明细进 `score_breakdown`
4. 评分单测锚点重写（旗舰 63 → 85 型）；job_posting 测试改巡检语义

## 九、验收（质量优先小闭环）

- **里程碑：50–100 条三问齐备的 S/A 商机，产品负责人人工核一遍觉得靠谱**
- 度量挂已有质检页：S+A 占比（qualified 池）≥20%（PRD §十二）+ 三准确率目标线不变
- 运营侧依赖（代码不能替）：产品负责人申请配置 `META_ADS_ACCESS_TOKEN` + 开启 `SCHEDULER_ENABLED=true`

## 十、明确不做（边界）

- 平台底座（任务系统/去重/线索池/跟进/RBAC/质检）不动
- LLM 语义判定层（Ollama）延后 V1.5
- TikTok Creative Center / Google Ads Transparency 采集器后补（出海指数对应信号位留空）
- 存量数据不清零（jobui 的 cn_domestic 留培育池，只清黑名单污染）

## 附：2026-09-01 需求裁决（用户审核后修订，覆盖正文冲突处）

1. **目标买家修订**：货代/物流/代运营/客服外包等出海中介服务商**不是**目标客户（正文的「出海服务」行业删除，目标行业为四类：跨境电商/品牌DTC、游戏App、制造业出海、出海SaaS与建站工具服务商）。建站/工具服务商（Shopline/Shoptop 类）**是**买家。
